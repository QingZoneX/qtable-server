Planned release type: **Open Source Preview / Alpha**

Draft started: 2026-09-02

> This file is a release-note draft. The QTable repositories are now public and developed in the open, but `v0.1.0-alpha` must not be represented as a published release until the exact-revision CI, full-stack E2E and tag/release gates below are complete.

## What this release is intended to represent

This is the first public open-source Alpha baseline for QTable. The core product is usable and permission-aware, while platform APIs, migrations, large-table behavior and AI/Agent contracts may continue to evolve before v1.0.

## Product capabilities

- Grid, Kanban, Gantt, Calendar and Gallery.
- Filters, sorting, grouping and named views.
- Formula, Relation, Auto Number and Workspace Member fields.
- Dashboard widgets and public sharing with permission safeguards.
- OAuth2 + S256 PKCE.
- Row-level permissions.
- ChangeSet/audit foundations.
- AI goal-to-workspace generation.
- AI task planning, workload estimation and member assignment.
- AI Project Steward.
- Preview/confirm/apply AI action plans.
- AI-generated views and dashboards.
- QNote/Clipper Source Inbox.

## Open-source readiness work

- Development-memory and runtime-data cleanup.
- Standardized demo data.

- Release/version metadata.
- Public source repositories: `QingZoneX/qtable-server` and `QingZoneX/qtable-web`.

## Known Alpha boundaries

- Template, dashboard and large-table performance work continues to evolve.
- Self-hosted / BYO AI will receive additional hardening.
- Table-as-API and Connector platform work remains on the roadmap.
- Existing startup schema repair remains temporarily available alongside the Alembic baseline for upgrade compatibility.

## Upgrade guidance

Before upgrading a real deployment:

1. back up PostgreSQL and object storage;
2. deploy to staging;
3. run `alembic upgrade head`;
4. run application smoke tests;
5. only then roll out production.

## Final publication gate

Remove `DRAFT / NOT YET RELEASED` only after all of the following are true:

1. `QingZoneX/qtable-server` Backend CI succeeds on the exact reviewed server `main` SHA.
2. `QingZoneX/qtable-web` Frontend CI succeeds on the exact reviewed web `main` SHA.
3. Full-stack release E2E executes against those exact revisions and retains its revision/screenshot/trace evidence.
4. Open-source readiness, dependency, license and container security gates pass for the release revisions.
5. The verified `v0.1.0-alpha` tag/release is created from the exact approved revision set.
6. Docker artifacts, when published, are produced by the release workflow from those verified revisions rather than by an unrelated manual build.

Repository visibility is no longer a future release gate: both source repositories are already public. Public visibility alone, however, does not make an arbitrary commit or image an official release artifact.

A workflow created without a real execution is not release verification and must never be treated as green evidence.
